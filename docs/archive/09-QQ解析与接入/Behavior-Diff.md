# 09 QQ解析器收敛 — 旧实现与当前Core的行为对照

本记录概述旧实现中观察到的行为

| 行为 | 旧实现 | 当前Core与本阶段处理 |
|---|---|---|
| 入口 | 候选解析会先尝试外部路线，再尝试QQ自身接口 | `QQProvider.resolve`统一校验身份与选项后进入有序路线；删除重复资格判断 |
| 路线顺序 | 外部路线按固定顺序尝试，之后回到平台接口 | Provider只保留一个顺序入口；顺序配置与服务端资格分开 |
| 执行资格 | 路线可用性与解析顺序交织在一起 | 默认仅启用平台接口；外部路线需要明确资格，不由顺序配置自行解禁 |
| vkeys请求 | 可按多个品质档位重复尝试 | 当前若实现单次请求，只使用明确档位；请求档位不等于编码证明 |
| 会话签名路线 | 会建立临时会话、生成请求签名并携带会话Cookie | 会话只在适配器请求期间存在，不共享平台Cookie，不跨调用缓存 |
| URL-only响应 | 有些外部服务只返回URL，调用方可能把请求身份当成响应身份 | URL-only只表示请求绑定；缺少独立录音证据时不作为已确认媒体发布 |
| 身份状态 | 录音身份状态和请求参数可能在多个层重复保存 | 响应MID直接决定身份核验；可由MID推导的字符串状态不另存 |
| 时长筛查 | 时长接近搜索结果可用于排除明显错误录音 | 时长近似不能证明录音或版本相同；当前发布条件要求更强身份依据 |
| Tang结果 | 响应可包含多个播放字段，存在选到伴奏或错版本的风险 | 适配器只选择原曲字段并核对返回MID；可选标题/歌手核验不替代身份检查 |
| 媒体检查 | 旧流程可能在不同层重复探测媒体 | 当前外部路线完成身份核验后只进行一次有界媒体读取；后续流传输独立验收 |
| 失败回退 | 多条外部路线失败后回到平台接口，异常范围较宽 | 统一总预算、取消传播和明确权限错误；仅临时失败按策略继续 |
| 结果公开 | 临时URL和路线信息可能与搜索对象共同存在 | 上游URL留在私有媒体结构中，公开DTO不增加URL或路线ID |

当前路径由 `QQProvider.resolve`、路线分发、对应适配器、请求工具和媒体验证组成。不同协议保留各自小型适配边界；Store、Lease和Range传输继续复用统一实现。

当前外部路线资格不足时，服务不会发起外部歌曲请求。即使以后具备明确的使用条件，URL-only结果仍需要满足录音身份要求，才能进入正式媒体路径。受控验证、历史样本结果和当前在线可用性分别记录。
