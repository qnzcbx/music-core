# 09 QQ解析与接入 — QQ认证流程研究来源

## 范围

本记录仅总结公开实现作为研究来源时可见的认证与调用边界。公开源码快照只能说明该快照中的实现，不能据此确认线上部署版本或服务授权。未记录本机路径、账户凭据、会话值或签名令牌。

## 研究观察

- QQ 解析服务的公开实现涉及账户会话、设备身份及服务端签名等不同机制。它们彼此独立，不能将登录状态、设备标识、服务调用签名和音乐平台会员权限视为同一凭据。
- 公开代码中可见的旧签名流程依赖服务端发放的签名材料。若引导响应未提供该材料，客户端不应以空值继续签名请求。
- 服务端到服务端的令牌或断言属于服务配置，不应移入客户端，也不能作为平台内容权限的证明。
- 单次匿名响应只能描述该次请求；不能推断部署版本、其他用户状态、服务长期可用性或内容授权。

## Music Core 实现边界

QQ 解析器将候选路线与官方路线分开配置，并在必要凭据缺失时停止该路线。URL-only 结果按其证据等级处理，不会自动升级为已确认媒体。当前可用路线和默认顺序见 [后端说明](../../../server/README.md) 及 [QQ 解析归档](README-Resolver-Audit.md)。

研究来源仅用于理解协议行为。Music Core 不依赖、导入或分发研究来源的实现，也不保存研究期间观察到的上游地址、令牌或会话材料。
