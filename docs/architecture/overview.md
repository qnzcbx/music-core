# 系统架构概览

Music Core 由 Vue 客户端与 FastAPI 服务组成。客户端负责交互、单一音频播放实例及队列状态；服务端负责来源适配、媒体解析、流式代理、下载任务、歌词和本地文件接口。

```text
搜索：Vue → /api/search → Provider → SongCandidate → 搜索结果
播放：曲目身份 → /api/playback/open → Resolver → MediaStore + PlaybackLease
      → 本地 Range 代理 → 唯一 HTMLAudioElement
下载：品质选项 → DownloadManager → 原始媒体校验 → (可选 FFmpeg) → 最终文件
```

## 模块边界与状态归属

- `server/app/main.py` 创建 FastAPI 应用，在应用生命周期中初始化共享 HTTP 客户端、四个 Provider、MediaStore、PlaybackLeases、DownloadManager、封面读取和歌词缓存，并在关闭时清理资源。
- `server/app/providers/` 将各来源的搜索、曲目详情和媒体解析封装在 Provider 中。Resolver 是来源内的解析策略；它不改变公共曲目身份或客户端 API 契约。
- `server/app/models.py` 定义跨层曲目身份及搜索、播放、下载等数据模型。对外的媒体响应不包含私有上游 URL 和请求头。
- `server/app/core/media_store.py` 保存播放期间所需的私有媒体信息；PlaybackLease 管理客户端会话的有效期。媒体 URL 不作为持久队列数据交给客户端。
- `server/app/downloads.py` 管理下载选项、内存任务状态、并发工作和本地文件接口。下载任务重新按曲目身份解析媒体，不复用播放 Lease。
- `server/app/transcode.py` 只在支持的输入和输出组合下调用 FFmpeg，并在发布前检查输出。
- `web/src/` 拥有界面状态。搜索 composable 获取并整理各来源的结果；播放器 composable 创建一个共享 HTMLAudioElement；队列 store 持有曲目身份和元数据快照。
- `server/tests/` 和 `web/tests/` 存放自动化回归测试；长期专项验证脚本及其用途见[后端专用说明](../../server/README.md)。

## 搜索：Provider 到客户端

1. 客户端按已选来源调用 `POST /api/search`，请求包含来源 ID、关键词、分页参数。
2. 服务端通过来源 ID 选择 Provider。各 Provider 负责来源协议、分页和结果转换。
3. Provider 返回统一的 `SongCandidate`，包含平台曲目 ID、标题、歌手、专辑、时长和可用封面地址等展示字段。
4. 客户端按来源保留搜索结果与游标，并将统一曲目数据传给搜索列表、播放器或下载界面。

封面是搜索/API 元数据中的独立 URL。客户端可直接用于展示；`/api/covers` 为部分来源的封面图片提供受限读取代理，客户端再从图片提取颜色。封面图片不因此成为音频文件的一部分。

## 在线播放、Lease 与失败恢复

1. 客户端以稳定的来源 ID 和平台曲目 ID 调用 `POST /api/playback/open`。
2. Provider/Resolver 重新解析媒体。服务端验证目标后，把上游 URL 和必要请求头保存在 MediaStore，并创建 PlaybackLease。
3. API 返回公开媒体信息、本地流地址及 Lease 时长；私有上游信息不会写入客户端队列或公开响应。
4. 唯一的 HTMLAudioElement 播放本地流地址。服务端的 `GET/HEAD /api/playback/{key}/stream` 校验 Lease，再代理上游字节范围请求，并流式返回内容。
5. 客户端续租；切歌或释放会关闭 Lease。服务端定期清理过期会话，应用关闭时清理存储并关闭客户端。

`usePlayer` 创建并持有唯一 Audio，底部播放器、播放页和队列控制共享该实例。队列持有曲目身份及标题、歌手、专辑、时长和封面等展示快照，不持有媒体 URL。播放恢复逻辑会在当前选择发生流错误时有限重试解析，恢复播放位置、音量、静音和播放速率；自动恢复次数受限，用户仍可手动重试。恢复、切歌和页面退出时会协调旧 Lease 的关闭，避免播放器状态与服务端媒体资源脱节。

## 下载与品质选择

1. 客户端通过 `POST /api/downloads/options` 查询指定身份、来源及目标格式的可用品质。
2. 创建下载任务后，DownloadManager 重新解析该曲目并流式获取原始媒体。它限制同时活动任务数，检查响应长度、文件头、格式/编码和所选品质。
3. 原始保存模式将已验证的上游字节写入临时文件；此路径不调用标签写入器，也不主动写歌曲名、歌手、专辑、封面或歌词。最终文件采用不覆盖现有文件的发布方式。
4. 对支持的 FLAC→MP3 转码，服务端调用配置的 FFmpeg/FFprobe，验证源文件、输出格式并完整解码检查后发布。该命令只映射音频流、排除视频/封面流并使用 `-map_metadata -1`，因此不会保留或重建输入标签、封面和歌词。
5. `GET /api/downloads/files` 返回文件名、大小、格式和修改时间等文件清单信息。服务端按 Range 流式提供本地文件；文件列表 API 不读取嵌入标签。

### 下载文件内部元数据审计

代码路径确认，原格式/直通下载保留的是上游媒体字节，因此上游文件已有的内嵌标签可能随文件保留；DownloadManager 不主动生成标签。转码路径主动移除元数据并只映射音频流，不会重建标签、封面或歌词。

在线搜索结果中的标题、歌手、专辑、封面和歌词是独立 API/客户端数据，不等同于下载文件内部元数据。歌词 API 返回解析后的歌词文档，客户端按播放时间同步；源码中未发现保存 `.lrc` 文件的功能。

## 歌词：独立数据流

客户端按当前曲目身份调用 `GET /api/lyrics`。服务端向对应 Provider 获取来源歌词、转换为统一歌词文档，并通过短时缓存复用查询结果。客户端解析文档并以 Audio 的当前播放时间同步呈现。歌词与播放媒体、下载任务和音频文件标签分别管理；当前没有把歌词写入媒体文件或导出 `.lrc` 的实现。

## 本地文件与本地播放

下载目录下的顶层音频文件由服务端扫描。当前实现按文件名扩展名与文件头识别 MP3、M4A、FLAC 和 Ogg，返回文件 ID、文件名、大小、格式及修改时间，并通过本地 Range 接口提供字节流。文件扫描和清单接口不读取 ID3/Vorbis/MP4 标签。

本地播放器仍使用共享的 Audio 实例。选择本地文件时，客户端优先使用当前内存下载任务中的标题、歌手及临时封面；若任务记录不存在，则以文件名作为标题、歌手留空，专辑和封面为空。浏览器读取音频时长。下载任务及其封面映射不作为本地文件的持久元数据保存，因此重启后文件列表不能恢复这些展示信息。

## 当前边界

- 来源接口、可访问曲目和可用品质可能变化；有限真实样本不能推出全部歌曲长期可用。
- Provider/Resolver 接管来源差异，公共模型/API 负责统一契约；下载和播放解析各自管理任务及资源生命周期。
- 本地 API 默认绑定回环地址，不包含用于公网部署的认证和访问控制。
- FFmpeg 能力取决于本机安装版本和编码器；未配置或验证失败时，转码品质不可用或任务失败。
