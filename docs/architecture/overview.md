# 系统架构概览

Music Core 由 Vue 客户端和 FastAPI 服务组成。客户端负责搜索界面、播放队列、歌词同步和下载交互。服务端负责来源适配、媒体解析、流式代理、歌词获取及下载交付。本机模式另提供音乐库索引与文件管理。

```text
搜索：Vue → /api/search → Provider → SongCandidate → 搜索结果
播放：曲目身份 → /api/playback/open → Resolver → MediaStore + PlaybackLease
      → Range 代理 → 共享 HTMLAudioElement
下载：曲目身份与保存选项 → DownloadManager → 校验媒体 → 可选转码
      → 网页模式：临时成品 → 浏览器保存到当前设备
      → 本机模式：保存到本机音乐库 → 登记文件索引
```

## 模块边界与状态归属

- `server/app/main.py` 创建 FastAPI 应用，初始化共享 HTTP 客户端、各来源 Provider、播放会话、下载管理器和缓存，并在关闭时释放资源。
- `server/app/providers/` 封装来源差异。Provider 负责搜索、详情及媒体解析，Resolver 是来源内部的媒体解析策略。解析策略可以变化，曲目身份和公共 API 契约不随之改变。
- `server/app/models.py` 定义曲目身份及搜索、播放、下载的数据模型。公开媒体响应不包含私有上游 URL 或请求头。
- `server/app/core/media_store.py` 保存播放所需的私有媒体信息。PlaybackLease 独立管理播放会话的有效期。
- `server/app/downloads.py` 管理品质检测、下载任务和文件交付。`server/app/transcode.py` 负责支持的音频转换及校验。
- `web/src/` 管理界面状态。搜索逻辑按来源维护结果和游标。播放器由 `usePlayer` 持有，队列保留曲目身份和展示信息，不保存媒体 URL。
- `server/tests/` 和 `web/tests/` 存放自动化回归测试。专项验证工具见[后端专用说明](../../server/README.md)。

## 搜索与展示数据

客户端按所选来源调用 `POST /api/search`，提交关键词和分页参数。服务端由对应 Provider 处理请求，将平台结果整理为统一的 `SongCandidate`。客户端按来源维护结果和游标，并将曲目身份与展示信息交给搜索列表、播放器和下载界面。

封面作为独立的展示数据提供。客户端可以直接显示封面，部分来源也可以经 `/api/covers` 受限代理读取。封面展示和取色不会修改音频文件。

## 在线播放与失败恢复

1. 客户端用来源 ID 和平台曲目 ID 调用 `POST /api/playback/open`。
2. Provider 解析媒体。服务端验证媒体目标，将私有上游 URL 和必要请求头存入 MediaStore，再分配 PlaybackLease。
3. 客户端使用返回的流地址播放。`GET/HEAD /api/playback/{key}/stream` 校验 Lease，代理上游字节范围请求并流式返回内容。
4. 客户端在播放期间续租，切歌或释放时关闭旧 Lease。服务端清理过期会话。
5. 流出错时，客户端有限次重新解析，并尝试恢复播放位置、音量、静音和播放速率。自动重试耗尽后，仍可手动重试。

底部播放器、播放页和队列共享同一个 `HTMLAudioElement`，本机音乐库播放也复用该实例。

## 下载品质与交付

客户端通过 `POST /api/downloads/options` 查询选定曲目的可用品质和保存方式。明确指定的品质不可用时，不自动降档。创建任务后，DownloadManager 按曲目身份重新解析媒体，不复用播放 Lease。

下载任务限制并发，流式写入临时文件，并检查响应长度、文件头、格式和品质。原格式保存保留通过校验的上游音频字节。对支持的 FLAC 转 MP3，服务端使用 FFmpeg 和 FFprobe 转换并验证输出。转码能力不可用时，只禁用转换，不阻止保存已确认可用的原格式。

| 模式 | 成品交付方式 |
| --- | --- |
| 默认网页模式 | 后端短期暂存成品，再以附件交给浏览器保存到打开网页的设备。不登记到永久音乐库，网页也不读取浏览器的下载目录。 |
| 本机模式（`MUSIC_CORE_LOCAL_MODE=1`） | 成品以不覆盖已有文件的方式写入后端所在机器的指定音乐库，并登记文件索引，供本机播放和管理。 |

## 本机音乐库与持久化

服务端扫描已知库目录的顶层音频文件，按扩展名和文件头识别 MP3、M4A、FLAC 和 Ogg。`GET /api/downloads/files` 提供文件清单，本机音频通过 Range 接口读取。

- **下载任务状态**保存在进程内，重启后不恢复旧任务的运行状态。
- **本机音乐库索引**独立持久化到 SQLite。应用发布的成品可登记已有的展示元数据。手动放入库目录的文件可被扫描发现，但不因入库自动获得在线曲目信息。没有可用标题时，界面可以用文件名展示。
- **音频内嵌标签**不是音乐库展示元数据的来源。扫描和清单接口不解析 ID3、Vorbis 或 MP4 标签，不能从索引持久化推断所有在线展示字段都会恢复。

## 文件标签与歌词

原格式保存不改写音频文件，因此上游已有的内嵌标签可能随文件保留。应用不会主动写入标题、歌手、专辑、封面或歌词。转码输出仅保留音频，不保留或重建上游标签、封面和歌词。

在线歌词单独通过 `GET /api/lyrics` 获取。服务端按曲目身份从对应来源取歌词、统一格式并短时缓存，客户端按当前播放时间同步显示。在线歌词不会写入音频文件，当前也不导出 `.lrc`。

## 当前边界

- 搜索、播放与下载是不同的能力。搜索命中或播放成功，不保证能够下载完整音源或取得指定品质。
- 来源接口、可访问曲目和可用品质可能变化，已有样本不代表整个曲库持续可用。
- 本地服务默认绑定回环地址，当前配置不包含公网部署所需的认证和访问控制。
