## 搜索差异：缺失的是请求参数

对照同一关键词“洛神赋 银临”，原版稳定身份为酷我 `235133157`，歌手银临、时长 206 秒、专辑“新神榜：杨戬 电影原声带”。不同 DJ 录音 ID 为 `524552001`、`489880753`，没有与原版混淆。

旧 Lab 的 `server/app/provider_adapter.py:metadata_search` 调用 vendor 中 `KuwoMusicClient._constructsearchurls`，只取指定页；原库 URL 参数包含 vipver=1、cluster=0、strategy=2012、issubtitle=1、show_copyright_off=1。新 Core 使用相同 searchMusicBykeyWord 端点及 all/ft/client/pn/rn/rformat/encoding/mobi，遗漏上述参数。两者都保留上游顺序，没有在本地按歌名重排。旧 HTTP 地址本轮返回 301，使用相同 HTTPS 端点做参数消融，排除协议与请求头变化的干扰。

运行 `server/scripts/investigate_kuwo_search.py`，保存 24 组真实上游公开元数据投影：[完整对照证据](kuwo-comparison.json)。关键结果：

| 请求 | TOTAL | 原版位置 |
| --- | ---: | --- |
| 原 Core 参数，rn=10 | 387 | 首批没有；可访问的前 10 页共 100 条均未找到 |
| 原 Core 参数，rn=15 | 387 | 首批没有 |
| 旧完整参数，rn=10 / rn=15 | 1712 | 两者都是第 1 页第 1 条 |
| 只添加 vipver=1 | 1711 | 第 1 页第 1 条 |
| 从旧完整参数仅去掉 vipver | 388 | 首批没有 |
| 仅加 cluster=0 / strategy=2012 / issubtitle=1 | 387 | 首批没有 |
| 仅加 show_copyright_off=1 | 388 | 首批没有 |

因此本轮直接原因是缺少 vipver=1 改变了上游返回结果集合；单纯扩大首批数量不能修复。没有证据表明是伴奏过滤，也没有把原版当作后续第二、第三页结果。未扫描超过旧 Core 十页上限的全部 387 条，不宣称已遍历该接口的全部曲库。

修复只恢复有消融证据的 vipver=1，不硬编码歌曲、改关键词或人工调整排序。其余旧参数保持未迁入；例如 show_copyright_off 会额外改变 TOTAL，但不是此次原版缺失的决定因素。未将这个搜索参数解释为播放授权，也未修改取链和权限判断。

## 转换、截断与展示追踪

原 Core 原始 abslist 没有原版 ID，因此它尚未进入 SongCandidate 转换；不存在前端先收到原版再丢弃的证据。相同原版在旧完整参数和单独 vipver 响应中均能通过现有 `candidate_from`，无需修改过滤器。

Provider 仍仅丢弃缺少有效录音 ID/标题等损坏条目，按稳定身份去重，再保留上游顺序。rows[:limit] 与请求 rn/pageSize 等一致。前端仍按 `[providerId, platformId]` 去重，歌曲分组仅影响展示，具体版本身份独立；展开与收起保留，不新增原版优先规则。

修复后实际新 Vue 首批第 1 条为原版 `235133157`。只添加 vipver 时，上游标题带“洛神赋-电影《新神榜：杨戬》插曲”副标题，旧完整参数标题为“洛神赋”；前端如实展示返回元数据，未为通过断言删改标题。结果见 [真实验收](real-result.json)，包含原版安全元数据和各批条数、游标。

## 15 条契约与独立分页

FastAPI SearchRequest 默认及上限由 10 改为 15；四个 Provider 的输入范围和 QQ/网易云/咪咕的页大小游标校验同步兼容 15。酷我仍用 pn=0 起算，其他来源沿用原页码/offset 换算；所有游标继续绑定页大小，原十页上限保留。旧调用者传 1～10 仍兼容，超过 15 由请求校验拒绝。TypeScript SearchRequest 本身是可选 number，无需更改字段结构；前端实际请求固定 limit=15。

`useCoreSearch.ts` 为各来源保存独立 cursor、状态、AbortController 和成功游标集合。一个来源在途时不能并发加载自身下一页；成功游标不重复请求，返回已消费游标时停止该来源。批内及跨页重复身份都会去重，失败页保留已有结果和原游标，只能通过“重试此来源”重试，不自动无限重试。

下一批选择仍可加载的来源，等待首个来源完成即可释放本轮调度，其余来源保留各自请求，不被取消。某来源耗尽、失败或较慢，不阻止其他健康来源推进。新搜索、来源集合变化取消旧请求、清空游标与成功记录、增加代次；无法及时取消的晚到结果同样不会覆盖新结果。

SearchView 的来源选择自动刷新当前搜索。设置页仍只保存偏好，离开设置返回搜索时应用；没有增加更新搜索按钮。相同关键词再次回车或点击搜索图标会从第一页重新搜索，而不是追加旧结果。

## 无限滚动与阅读位置

使用已安装 VueUse 的 `useInfiniteScroll`，由 SearchView 根元素找到 AppShell 真正滚动的 `#app-content`，距离底部 320px 加载。未监听 window，也没有改 AppShell 或新增依赖。

每次搜索最多允许两批无交互自动补屏；额度耗尽后，需要向下滚轮、向上拖动内容或滚动键等用户输入，才给下一批一次许可。内容不足一屏时也能通过下一次滚动意图继续，不需要显式加载按钮；VueUse reset 重新测量，但不重置来源游标。该上限不是总分页上限，不影响正常继续滚动。

请求下一批前锁定已有组代表版本；响应更新 DOM 前记录当前可见歌曲的位置，更新后补偿 scrollTop。定位到歌曲行而非整个组，展开组内插入版本时也能尽量保持阅读位置。错误提示和重试入口放在底部，避免新增上方段落将已读歌曲向下推。新关键词、来源集合和同词重搜重置滚动到顶部。

计数在仍有下一页、请求在途或某来源失败时显示“已加载 N 首”，只有所有来源结束才表达最终数量。加载和结束反馈位于底部，失败保留已有歌曲并提供手动重试；没有“加载更多”按钮。
